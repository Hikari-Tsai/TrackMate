# C 層實驗：軌名 → 樂器 id（e5-small / Qwen3-Embedding-0.6B / bge-m3）

日期：2026-10-26　｜　索引：`kb/mix_naming.json`（2,081 筆別名）　｜　硬體：Apple Silicon（MPS）

重現：`uv run --no-project --python 3.12 --with numpy --with rapidfuzz --with "sentence-transformers>=3" --with torch python run_compare.py --models fuzzy,e5,qwen_sym,bge`

## 指標定義

| 名稱 | 定義 |
|---|---|
| **Top-1 準確率** | 每筆都強制選最相似的一種樂器、不允許「不知道」時，選對的比例。因為每筆都有答案，此時 Precision = Recall = 準確率。 |
| 精確 / 大類 | Top-1 準確率的兩種判定：**精確** = 選到正確樂器（或標註允許的替代）；**大類** = 至少大類正確（例如 kick_in 判成 kick 也算對）。 |
| **Recall@k（R@1 / R@3 / R@5）** | 模型依相似度列出前 k 個**不同的樂器**，正確樂器出現在其中的比例（精確判定）。R@1 就是 Top-1 精確準確率。R@3、R@5 代表「把前 3 或前 5 個候選交給下一步，例如音訊判斷或使用者選單，正確答案有多大機率在裡面」。 |
| **Precision（精確度）** | 只在分數 ≥ 門檻時才自動改名。被自動改名的軌之中，改對的比例；非樂器名稱被改名也算改錯。 |
| **Recall（召回率）** | 同一門檻下，所有應該改名的軌之中，被**正確**自動改名的比例。 |
| R@P95 | 把 Precision 固定在 ≥ 95% 時，能達到的最大 Recall。門檻用「最高分 s1」或「第一名與第二名的分差 margin」，表中寫成 s1 / margin。 |

## 結論

1. **中文：bge-m3 沒有比 Qwen 好。** Qwen 在兩項中文測試都最好（中文留一法精確 44.2，bge 35.8，e5 27.5）。bge-m3 介於兩者之間。
2. **日文：bge-m3 最好。** 在跨語言和留一法兩項都領先 Qwen 13–17 個百分點。
3. **真實軌名剩餘集：bge-m3 的 Top-1 最高**（精確 75.8），而且反例分數最低（0.69），代表比較容易用門檻區分「是樂器」和「不是樂器」。但 R@P95 仍是 e5 略高，加上樣本只有 33 + 21 筆，差距不具統計意義。
4. **中文和日文的 R@P95 全部接近 0。** 任何模型遇到字典沒收錄的中日文寫法，都無法在 95% 精確度下自動改名。所以中日文應該**靠擴充字典（A 層）解決**，embedding 只能提供候選，或在灰色區和音訊結果一起判斷。
5. **前 5 個候選的涵蓋率明顯較高。** 英文沒看過的別名 R@5 達 86–88%，日文 bge-m3 達 89–91%，中文 Qwen 為 66–72%。所以 C 層很適合當「候選產生器」：把前 3 到 5 個候選交給音訊判斷重新排序，或放進使用者確認選單，而不是直接採用第一名。
6. Qwen 的中文優勢，主要出現在需要理解字義的詞：鼓 → drums、銅鈸 → cymbals、房間收音 → drum_room。bge-m3 則較擅長「中文 + 英文縮寫」混寫：貝斯di → bass_di、808貝斯 → bass_808。

## 限制

- 真實軌名測試集是手寫的，和字典出自同一人；剩餘集樣本小。
- 延遲是在 MPS 上逐筆量測，沒有做 ONNX 轉換或 int8 量化。
