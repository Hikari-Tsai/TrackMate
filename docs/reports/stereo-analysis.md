# 立體聲／單聲道判斷

分軌檔常常是「假的立體聲」：一個單聲道來源被存成兩聲道，可能偏左或偏右（Pan）、只有一邊有聲音，或是另一邊極性反相。TrackMate 需要判斷每個雙聲道檔是不是其實只有一個來源，如果是，還要在不改變音量和音色的前提下還原成 mono。

- 程式：[`stereo_analysis/stereo_analyzer.py`](../../stereo_analysis/stereo_analyzer.py)
- 測試：[`stereo_analysis/test_stereo_analyzer.py`](../../stereo_analysis/test_stereo_analyzer.py)（27 個）、案例 [`stereo_analysis/cases.py`](../../stereo_analysis/cases.py)

## 方法：共變異數的 rank-1 殘差

### 1. 為什麼不直接比較 L 和 R

單一 mono 來源放進立體聲時，不論 Pan 位置、Pan law 或極性為何，都可以寫成：

```
L(t) = a·s(t)    R(t) = b·s(t)
```

a、b 是兩個常數。用「L 是否等於 R」或「L−R 是否接近 0」來判斷，只有置中（a = b）時才對：

| 情況 | L−R | 直接比較的結果 |
|---|---|---|
| 置中（a = b） | 0 | mono，正確 |
| 往左 Pan（a = 1、b = 0.5） | 0.5·s | 誤判成立體聲 |
| 極性反相（b = −a） | 2·s | 誤判成立體聲；而且直接 L+R 會完全抵銷 |

把每個取樣點的 (L, R) 畫成平面上的一個點，這三種情況的點都落在**同一條通過原點的直線**上，只是斜率 b/a 不同。真正的立體聲則會散成一團。所以 TrackMate 判斷的是「點是不是排成一條線」，而不是「L 等不等於 R」。

### 2. 共變異數矩陣

只用有聲音的音框（見下方第 5 點），先去掉每個音框的直流成分（DC 偏移不能被當成立體聲寬度），再累加：

```
C = [ ΣL²   ΣLR ]
    [ ΣLR   ΣR² ]
```

C 描述點雲朝哪些方向散開。它的兩個特徵值：

- **λmax：** 沿主軸方向的能量，也就是最貼合點雲的那條直線。
- **λmin：** 垂直於主軸的能量，也就是「不在那條線上」的殘差。

2×2 對稱矩陣可以直接用公式求，不需要數值分解（[`_principal_axis`](../../stereo_analysis/stereo_analyzer.py)）：

```
λ = (ΣL² + ΣR²)/2 ± √( ((ΣL² − ΣR²)/2)² + (ΣLR)² )
θ = ½ · atan2(2·ΣLR, ΣL² − ΣR²)        主軸和 L 軸的夾角
```

### 3. rank 1 是什麼意思

rank（秩）是一個矩陣裡真正獨立的方向有幾個；2×2 矩陣只可能是 0、1 或 2。

- **從矩陣看：** 第二列是第一列的倍數時，只有一個獨立方向，rank 是 1。這時行列式 ad − bc = 0，其中一個特徵值是 0。例如 `[[1, 0.5], [0.5, 0.25]]`：1 × 0.25 − 0.5 × 0.5 = 0。
- **從點雲看：** rank 1 代表點只朝一個方向散開，全部排在一條線上（λmin = 0）；rank 2 代表兩個方向都有散開，是一團橢圓或圓。

| 點雲形狀 | rank | 意思 |
|---|---|---|
| 一條線（不論斜率、正負） | 1 | 只有一個來源，L 和 R 只是它的不同倍數：mono |
| 扁扁的橢圓 | 接近 1 | 大致是 mono，加上一點壓縮誤差或雜訊 |
| 一團圓 | 2 | L 和 R 各有自己的內容：真立體聲 |

真實音檔一定有一點雜訊，λmin 不會剛好是 0，所以用兩個特徵值的比值衡量「有多接近 rank 1」：

```
residual_db = 10 · log10(λmin / λmax)
```

| 檔案內容 | C（正規化後） | residual |
|---|---|---|
| 置中 mono（L = R） | [[1, 1], [1, 1]] | −∞（實際 −60 dB 以下） |
| 往左 Pan（R = 0.5·L） | [[1, .5], [.5, .25]] | −∞ |
| 極性反相（R = −L） | [[1, −1], [−1, 1]] | −∞（直線斜率為負） |
| 立體聲殘響（兩聲道相關係數 0.9） | 特徵值 1.9 和 0.1 | 約 −12.8 dB |
| 兩個不同來源（不相關） | ≈ [[1, 0], [0, 1]] | 0 dB |

門檻是 **−30 dB**：λmin 不到 λmax 的千分之一就算 mono。留這個餘裕，是為了容許 MP3/AAC 有損編碼和底噪。

**為什麼不用相關係數：** 相關係數會把兩個聲道各自標準化。Pan 得很偏時，弱的那一側只剩很小的訊號，它的雜訊會把相關係數拉低，結果被誤判成立體聲。特徵值的比值是用能量加權的，弱聲道的雜訊和 λmax 比起來很小，不影響判斷。

### 4. 主軸給出 Pan、極性和還原方式

- **Pan：** θ = 0° 是全左、45° 是置中、90° 是全右，換算成 −1 到 1：`pan = (|θ| − 45°) / 45°`。
- **極性：** 主軸斜率為負（cos θ · sin θ < 0）代表兩聲道極性相反。
- **還原 mono：** 不用 L+R，而是把每個點投影到主軸 (cos θ, sin θ) 上，權重再乘上 max(|cos θ|, |sin θ|)，讓音量和較大聲的聲道一樣；如果較大聲的聲道權重是負的，就整體翻轉，保留它的極性。這樣極性反相的檔案不會抵銷，有 Pan 的檔案音量也不會改變。

### 5. 判斷順序

1. **只用有聲音的音框：** 音框 0.1 秒，高於 −70 dBFS，且不比最大聲的音框低 50 dB 以上。長時間的靜音、淡入淡出、dither 雜訊都不會影響統計。
2. **單邊（hard pan）：** 一側比另一側低 30 dB 以上，就直接取大聲的那一側，不需要算矩陣。
3. **rank-1 測試：** 整首的 residual 低於 −30 dB，而且逐音框檢查時（每個音框門檻放寬 10 dB，即 −20 dB），像 mono 的音框要佔有聲能量的 95% 以上。後者避免「前半首 mono、後半首真立體聲」的檔案被整個轉成 mono。
4. **延遲的 mono：** 不是 mono 時，在最大聲的幾個片段用交叉相關，找出一邊比另一邊晚幾毫秒的情況（Haas 效果、間距麥克風）。這種檔案一加總就會產生梳狀濾波，所以保留立體聲。
5. 都不是，就是真立體聲。

## 判斷結果與建議動作

| 類型 | 意思 | 建議動作 |
|---|---|---|
| `mono_file` | 本來就是單聲道 | 保留 |
| `fake_stereo` | 單一來源（含 Pan、極性反相） | 投影成 mono |
| `hard_left` / `hard_right` | 另一邊沒有聲音或低 30 dB 以上 | 取有聲音的那一邊 |
| `delayed_mono` | 同一來源有時間差 | 保留（避免梳狀濾波） |
| `true_stereo` | 真的立體聲 | 保留 |
| `silent` | 沒有聲音 | 保留，標記 |
| `multichannel` | 超過兩聲道 | 保留 |

主要參數：
- 音框 0.1 秒。
- 絕對門檻 −70 dBFS，相對範圍 50 dB。
- 單邊判定 30 dB。
- mono 殘差門檻 −30 dB，容許 MP3/AAC 這類有損編碼。

## 在 TrackMate 中的使用
- **分析：** `/analyze` 會回傳每個檔案的類型和建議動作。前端依建議預設勾選「To mono」，使用者可以改。
- **轉換：** `/apply` 匯入前，用 `write_downmix` 寫出 mono 暫存檔，匯入後刪除。
